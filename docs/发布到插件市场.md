## 以后怎么发新版本（一次配置，之后两步）

**2026-09-25 已经发布过一次**：
- 仓库：<https://github.com/Andersen216/dsh-whale-girl-live2d>
- 市场 PR：<https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/pull/5882>
- Release：<https://github.com/Andersen216/dsh-whale-girl-live2d/releases/tag/v0.2.0>

把 token 存进 macOS 钥匙串一次（在你自己终端里跑，会提示你手动输入，**不会进 shell 历史**）：

```bash
security add-generic-password -a Andersen216 -s dsh-whale-girl-live2d-publish -w
```

之后发新版本只有两步：

```bash
# 1) 改代码、跑测试、改 package.json 的 version
npm test && npm run smoke
# 2) 一键发布（脚本自动从钥匙串读 token；仓库已存在，会直接推 + 更新市场条目）
npm run publish
```

撤销：钥匙串里删掉那条（`security delete-generic-password -s dsh-whale-girl-live2d-publish`），
或去 <https://github.com/settings/tokens> 吊销 token。

## 为什么名字长这样

- `dsh-whale-girl`、`dsh-whale-girl-pet`、`dsh-whale-pet` **在 npm 上都被别人占了**
  （分别是 nickkkkkk123123 / yanzwzz / eric0v0 的鲸鱼娘桌宠）。
  插件名撞车最坏的结果是**市场把别人的包装给用户**，所以必须挑一个两边都空着的名字。
- `dsh-whale-girl-live2d` 在 npm 与 GitHub 上**都空闲**，同时把「鲸鱼娘」和「Live2D」都写进去了。
- 展示名不靠包名：README 首行与市场 `description` 才是「这是干啥的」——
  中文名「鲸鱼娘桌宠 —— DSH 里的 Live2D 鲸鱼娘」，英文名
  “Whale Girl Pet — the Live2D whale-girl companion for DeepSeek Harness”。

## github.com 连不上时怎么推代码

有些网络环境里 `api.github.com` 通、`github.com:443` 不通：`git push` 会卡住或报
`Failed to connect to github.com port 443`。这时用 REST 的 Git Data API 推（blobs → tree → commit → 改 ref）。
脚本会先比对 tree 哈希，对不上就拒绝推送，不做破坏性操作：

```bash
GITHUB_TOKEN=<带 public_repo 的 token> node tools/push-via-api.mjs [本地提交sha] [owner/repo] [分支]
```

推成功后 GitHub 上的 commit sha 与本地不同（提交者信息由 API 补齐），但**文件内容逐字节相同** ——
可以用 `git -c core.quotePath=false ls-tree -r <本地sha>` 与
`GET /repos/:o/:r/git/trees/<sha>?recursive=1` 逐文件比对 blob 哈希来验证。
